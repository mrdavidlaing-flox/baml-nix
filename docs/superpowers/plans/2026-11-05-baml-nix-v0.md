# BAML v0 for Nix and Flox: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build BAML v0 (`baml-cli` and `python3Packages.baml-py`) from source as nixpkgs-style packages, use them from a Flox Python project through a local flake, and prepare a nixpkgs branch David can submit.

**Architecture:** Package files under `pkgs/` are plain `callPackage` functions with the same shape as nixpkgs. They use no flake inputs and no `self`. `flake.nix` (nixos-unstable is its only input) wires them in through an overlay. A Flox demo in `examples/flox-python/` installs catalog Python plus `baml-py` from the local flake. A spike first settles how Flox makes a flake-provided Python package importable.

**Tech Stack:** Nix flakes, nixpkgs `rustPlatform` / `buildPythonPackage` + `maturinBuildHook` + `rustPlatform.cargoSetupHook`, Flox 1.19.1, BAML v0.226.3, Python 3.14 (nixos-unstable default).

**Spec:** `docs/superpowers/specs/2026-11-05-baml-nix-v0-design.md`

## Global Constraints

- Build from source only: no PyPI wheels and no GitHub release binaries.
- Package files must not use fenix, crane, flake inputs or `self`. They must be `callPackage`-able unchanged from a nixpkgs checkout.
- Source: `fetchFromGitHub { owner = "BoundaryML"; repo = "baml"; tag = "v${version}"; }`, version `0.226.3`, Cargo workspace root `engine/`.
- Flake input: `nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable"`. No other inputs.
- `meta.platforms`: `lib.platforms.linux ++ lib.platforms.darwin` (x86_64 and aarch64). Tested: x86_64-linux here, aarch64-darwin by David.
- Keep the Darwin-specific inputs in from the start. Linux builds must not depend on them.
- `meta.license = lib.licenses.asl20`, `meta.maintainers` = David (see Task 6).
- The Flox demo references the flake locally (no GitHub repo).
- Never push anything: not to GitHub, and not to `mrdavidlaing/nixpkgs`. David submits the PR.
- RUSTFLAGS must include `--cfg tracing_unstable` (upstream requires it). Don't carry over `crt-static` or `OPENSSL_STATIC`.

## Review Focus

1. **Generator version pin.** `baml_src/generators.baml` declares `version "0.226.3"`. If that doesn't match the installed `baml-py`, `baml-cli generate` errors. The demo pins it to the packaged version, and Task 4 asserts the generated client's version equals `baml_py.__version__`.
2. **Both packages in one Flox env.** `baml-cli` and `baml-py` both install `bin/baml-cli`. A user installing both must not get a file-conflict build failure. Task 4 includes both in the demo manifest and gives `baml-cli` a higher priority number than `baml-py`.
3. **Interpreter mismatch.** The env's Python (Flox catalog `python314`, or the user's `python313`) may differ from the one the package was built against. abi3 should make the import work anyway. Task 3's passthru test imports `baml_py` under both `python313` and `python314`.
4. **Offline generate.** `baml-cli generate` must work with no network (the Nix sandbox, a plane). Task 3's passthru test runs `generate` inside the build sandbox.
5. **CLI reports the wrong version.** Built from a tarball with no `.git`, the version string could come out as empty or `0.0.0`. Tasks 2 and 3 assert `baml-cli --version` contains `0.226.3`.
